# Варианты интерфейса

Текущее обновление добавляет полосу прогресса и ETA к C++ CLI. Расчёт прогресса
и ETA отделён от отображения; пути результатов и кэш также имеют отдельные
интерфейсы. Это позволяет развивать UI без переписывания обработки аудио.

| Вариант | Сложность | Целесообразность |
|---|---|---|
| Текущий C++ CLI | Средняя | Реализован; достаточно для запуска одной записи |
| Go + Bubble Tea как оболочка | Высокая | Полезен при появлении интерактивной очереди и управления задачами |
| Qt Quick + C++ backend | Высокая | Подходит для выбора файлов, истории и настольного окна |
| Полная перепись backend на Go | Очень высокая | Сейчас не требуется; потребует повторного доказательства надёжности отмены и экспортов |

[Bubble Tea](https://github.com/charmbracelet/bubbletea) предоставляет модель
состояния, событий и отображения для терминальных интерфейсов.
[Qt Quick/QML](https://doc.qt.io/qt-6/qtqml-cppintegration-overview.html) позволяет
связывать интерфейс с логикой C++. Обе оболочки могут сохранить существующие
yt-dlp/FFmpeg/Whisper процессы и C++ реализацию их управления.

Первый шаг отдельного UI-проекта — документированный поток событий backend:
этап, общий прогресс, ETA, завершённые части, путь результата, статус и ошибка.
Он должен быть отделён от пользовательского stdout и диагностики инструментов.
Для Go оболочки предпочтительны отдельный процесс C++ и события JSON Lines;
это избегает зависимости от ABI и разбора русских сообщений. Qt интерфейс
также может начать с процессной границы, а позже использовать C++ адаптер.
В текущем обновлении этот протокол и интерфейсы не реализуются.

Обязательные требования будущего UI: Ctrl+C/закрытие окна передают отмену
backend, UI не объявляет успех до подтверждённого завершения, частичные результаты
и рабочее аудио сохраняются до границы завершения. Регрессии SIGINT, SIGPIPE,
падения работников и объединения экспортов остаются обязательными.
