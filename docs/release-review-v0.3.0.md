# Ревью кода v0.3.0 — 3 октября 2026

## Summary

PR выпускает хранение результатов по названию и дате, прогресс с ETA и
кэширование медиа как версию 0.3.0. Проверены изменения `dev` от master
`69f8776` до `79fd3b5`, включая код, тесты, CI и документацию; подготовка
выпуска дополнительно меняет номер версии и релизные документы.
Ревью выполнено по `code-reviewer` и `cpp-pro`, проверки — по
`verification-before-completion`.

## Соответствие требованиям

| Требование | Проверенное поведение |
|---|---|
| Название и дата каталога | `ResultPaths`: UTF-8, локальная дата, безопасное имя, коллизии без перезаписи |
| Прогресс и ETA | Веса по семплам всех частей; одна строка TTY, текстовый fallback, отключение |
| Повторное использование медиа | URL без downloader, aliases по extractor/id, лимит/LRU, refresh, offline |
| Раздельное хранение | `logs/`, `transcripts/`, `source.txt`; рабочее `audio/` сохраняется при ошибках |
| Вывод в HOME | `$HOME/Transcriptions`; явно заданный `--out` работает без HOME |
| Оценка интерфейса | `docs/interface-options.md`; TUI/GUI и переписывание backend не входят в выпуск |

## Minor issues

- `src/progress.cpp:28`: ETA пересчитывается с растущим elapsed при неизменном
  проценте, поэтому между обновлениями растёт. Это подтверждено длинным
  запуском и раскрыто в документации. Для следующего выпуска стоит измерять
  скорость по изменениям обработанной длительности и уменьшать remaining
  между ними. Возможная основа: `remaining = (total_samples - done_samples) /
  smoothed_samples_per_second`; отдельно проверить загрузку модели, смену
  очереди частей и длительные остановки. Нынешняя оценка приблизительная,
  не влияет на экспорт или статус и не блокирует выпуск.
- `src/media.cpp:87`: контекст браузера — строка профиля, а не идентификатор
  аккаунта. После смены аккаунта в том же профиле может использоваться прежний
  приватный снимок. Ограничение явно описано; `--refresh-cache` и `--no-cache`
  позволяют контролировать поведение. Если потребуется более строгая изоляция,
  можно добавить явный namespace пользователя без чтения секретов браузера.

## Positive feedback

- Процессы получают вектор аргументов через `posix_spawnp`; названия, URL,
  prompt и cookies не интерполируются в shell. Пути шаблонов yt-dlp экранируют `%`.
- RAII закрывает lock и процессы при исключениях. `flock` сериализует загрузку
  и публикацию, ожидание проверяет отмену; распознавание освобождает блокировку.
- Кэш проверяет владельца, права, symlink и lock-файл; LRU удаляет только
  управляемые записи. Копии в рабочем каталоге независимы от вытеснения кэша.
  Это не защита от злонамеренного процесса с тем же UID.
- Валидация исполняемого файла и границ субтитров происходит до публикации
  успеха. При ошибках остаются диагностика, аудио и частичный текст.
- Сохранился порядок завершения: проверить/закрыть экспорты, проверить stdout,
  записать completed, зафиксировать завершение, затем best-effort cleanup.
- Тесты проверяют наблюдаемое поведение: PTY/dumb, отмену, падение после вывода,
  независимость работников, порядок частей, cache misses/refresh/LRU/symlink.
